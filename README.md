# multi-agent-demo

## 虚构业务设定

虚构公司「极光办公」有三条产品线：极光笔记（个人版 69 元/年、团队版 199 元/年）、极光云盘（标准版 99 元/年、旗舰版 299 元/年）、极光日历（免费版、专业版 49 元/年）。两个演示账号 alice（买过极光笔记团队版、极光日历专业版）与 bob（买过极光云盘标准版）。四个智能体：

| 注册名 | 中文名 | 职责 | 工具 |
|---|---|---|---|
| product_consult | 产品咨询 | 价格、版本差异、功能咨询、购买建议 | `catalog_search` |
| order_query | 订单查询 | 只查**当前会话用户自己**的订单 | `order_lookup` |
| after_sales | 售后支持 | 激活、退款、发票、故障排查 | `ticket_create` / `faq_search` |
| kb_agent | 知识检索 | 对公开技术文档语料做知识问答 | `kb_search`（复用同级 rag-eval 检索器） |

这是演示项目，产品与数据均为虚构。

## 复现

Python 3.10+；默认 mock 路由不需网络或密钥。`rag-eval` 必须置于同级目录，并保留该仓库自身的公开 Vue 文档语料和索引数据：

```text
父目录/
  multi-agent-demo/
  rag-eval/
```

在本仓库根目录执行：

```sh
python -m pip install -r requirements.txt
python run_demo.py
python run_router_eval.py
python -m pytest tests -q
uvicorn app:app
```

双击 `web/index.html`，登录 alice 或 bob 后提问。也可调用 `/login` 获得会话，再向 `/chat` 发送 `session_id` 和 `question`；`/agents` 返回注册清单。演示账号为无密码登录，不适合真实身份认证。可选 `--router openai-compatible` 从 `BASE_URL`、`API_KEY`、`MODEL` 读取配置，需可访问的服务。

演示记录写入 `out/summary.json` 和 `out/trace.jsonl`；评测准确率、混淆表和错题写入 `out/router_eval.md`。数据从本仓库的 `data/` 只读加载；检索器导入同级 `rag-eval`，索引写入本仓库 `out/`。企业场景中知识库可对应内部文档库；演示使用公开技术文档语料，避免引入私有数据。

## 架构与边界

- Registry 为什么配置化：`agents.json` 统一声明名称、工具、路由词和处理入口，新增智能体可只新增配置项并复用已有处理入口，不必修改路由与主干；要增加全新业务能力仍需提供对应处理函数。
- 为什么显式划定路由边界：把技术术语型问题错分到售后比澄清或不答更损害信任，因此技术术语的优先级高于“怎么办”等表达。
- 为什么在召回层卡权限：只把 `kb_scope` 允许的文档交给分块和检索器；生成后再删除意味着越权内容已经进入候选或上下文。订单查询同样先按会话用户过滤。
- 为什么不信任前端身份：如果聊天请求能自行换用户 ID，就能越权查询他人信息。服务端校验会话、使用哈希保存的令牌查找用户；请求体出现 `user_id` 即返回 400。会话仅驻留内存、30 分钟过期。

复合问题按原顺序串行处理，而非并行抢答：后续决策可以参考前一步结果，轨迹与失败判定也更简单。Mock 逻辑、内存工单和会话、简化的关键词路由都只用于演示，不保证业务或安全生产能力。
